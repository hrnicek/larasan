# Security policy

## Supported versions

Larasan has no tagged release yet. Only the `main` branch is supported, and fixes land there.

## Reporting a vulnerability

**Please do not open a public issue.**

Report privately through GitHub's
[private vulnerability reporting](https://github.com/hrnicek/larasan/security/advisories/new).
It goes to the maintainer and to nobody else.

Useful in a report: what an attacker can do, the smallest reproduction you have, the commit you
tested, and whether it needs an authenticated account or a particular workspace role.

You should expect an acknowledgement within a few days and an assessment within two weeks. If a
fix is warranted, you will be credited in the advisory unless you would rather not be.

## What is in scope

The application in this repository: workspace and project authorization, tenant isolation between
workspaces, file access, broadcast channel authorization, the authentication flows Fortify serves,
and anything that lets one account reach another's data.

Out of scope: findings in a dependency that are already public and unpatched upstream, and reports
generated by a scanner with no demonstrated impact.

## What the application already assumes

A leaked UUID is
expected to be useless: every read proves its workspace scope inside the query, and the test suite
asserts the cross-workspace case for each resource. A report showing otherwise is exactly the kind
that is most welcome.
